# TASK: Refactor Fleet & Logistics Module (Haulage, Charter Booking & Weekly Running Expenses)

## Architectural Rationale & Business Justification (The "Why")

### 1. The Dual-Role Fleet Operational Model
The current fleet module treats vehicles as generic internal asset trackers. However, according to Mr. Emeka, the enterprise operates two distinct logistics functions:
* **Internal Sales Distribution Fleet**: Trucks/vans that load bakery, water, and popcorn inventory daily for sales rep distribution routes.
* **VIP Vehicle Logistics & Commercial Haulage Division**: A revenue-generating charter service where external vendors and corporate clients call in to book trucks or VIP vehicles for state-to-state transport and freight delivery across Nigeria.

### 2. 360° Statewide Pricing Matrix (With vs. Without Fuel)
Commercial haulage rates must not be manually guessed on every phone call. The system requires a pre-configured **Nationwide Route Rate Sheet** covering destination states across Nigeria. Every route must support two distinct pricing tiers:
* **Fuel-Inclusive Rate ("With Fuel")**: Company provides diesel/petrol for the entire journey.
* **Freight-Only Rate ("Without Fuel")**: Client/chartering vendor provides fuel for the truck.

### 3. Multi-Leg Layovers & Trip-Specific Incidentals
Logistics calls frequently involve multi-stop trips (e.g., Factory \\(\rightarrow\\) State A \\(\rightarrow\\) State B \\(\rightarrow\\) Destination). Furthermore, haulage runs incur variable road expenses—such as **driver allowances, security/police escort fees, local government levies, and toll charges**—which must be itemized per booking to calculate net trip profitability.

### 4. Weekly Fleet Fueling & Maintenance Reconciliation
Vehicles typically refuel once or twice a week (e.g., Mondays and Thursdays). Rather than forcing fuel and repair bills into single daily loaf/unit production costs, fleet running costs are aggregated over the **Sunday-to-Saturday operating week** to calculate weekly corporate operational overhead.

### 5. Application Context (DTOs & Dummy Services)
The application currently operates using Data Transfer Objects (DTOs) and mock/dummy data services. All pricing calculations, multi-leg layover aggregations, and weekly expense totals must be implemented cleanly at the DTO and mock service layer.

## 1. DTO & Data Contract Specifications

Create or update the following Data Transfer Objects:

```typescript
export type FuelOption = 'WITH_FUEL' | 'WITHOUT_FUEL';
export type VehicleStatus = 'AVAILABLE' | 'ON_TRIP' | 'MAINTENANCE' | 'INACTIVE';

export interface RouteRateDTO {
  id: string;
  originState: string;               // e.g., "Lagos"
  destinationState: string;          // e.g., "Rivers (Port Harcourt)"
  vehicleTypeRequired: string;       // e.g., "30-Ton Haulage Truck", "VIP Van"
  rateWithFuel: number;              // Standard rate including company diesel
  rateWithoutFuel: number;           // Discounted rate when client provides fuel
  estimatedHours: number;
}

export interface TripLegDTO {
  legNumber: number;
  originState: string;
  destinationState: string;
  fuelOption: FuelOption;
  legCost: number;                   // Derived from RouteRateDTO
}

export interface CharterBookingDTO {
  id: string;
  bookingRef: string;                // e.g., "LOG-20261005-01"
  customerName: string;
  customerPhone: string;
  vehicleId: string;
  vehicleRegNumber: string;          // e.g., "KJA-412AA"
  driverId: string;
  driverName: string;
  
  // Route & Multi-Leg Layover Details
  isMultiLeg: boolean;
  legs: TripLegDTO[];
  
  // Trip Incidentals
  driverAllowance: number;           // Daily/Trip driver stipend
  securityEscortFee: number;         // Security/police escort costs (if required)
  tollsAndRoadLevies: number;        // Checkpoint, union, and toll charges
  
  // Computed Financials
  grossCharterFee: number;           // SUM(legCost)
  totalTripIncidentals: number;      // SUM(allowance + security + tolls)
  netCharterRevenue: number;         // grossCharterFee - totalTripIncidentals
  
  tripStatus: 'BOOKED' | 'IN_TRANSIT' | 'COMPLETED' | 'CANCELLED';
  departureDate: string;
  returnDate?: string;
}

export interface WeeklyFleetExpenseDTO {
  id: string;
  operatingWeekStart: string;        // Sunday (YYYY-MM-DD)
  operatingWeekEnd: string;          // Saturday (YYYY-MM-DD)
  vehicleId: string;
  fuelExpenseTotal: number;          // Aggregated weekly diesel purchases
  maintenanceExpenseTotal: number;   // Servicing, tire repairs, spare parts
  incidentalsTotal: number;
  totalWeeklyRunningCost: number;
}

 Mock Data Service Logic (MockFleetService)
Implement the following business logic inside the mock fleet service:
calculateTripRate(legs: TripLegDTO[]):
Searches RouteRateDTO matrix for origin/destination pairs.
Applies rateWithFuel or rateWithoutFuel depending on the fuelOption selected for each leg.
Aggregates multi-leg trip fees to compute grossCharterFee.
calculateTripProfitability(booking: CharterBookingDTO):
totalTripIncidentals = driverAllowance + securityEscortFee + tollsAndRoadLevies.
netCharterRevenue = grossCharterFee - totalTripIncidentals.
getWeeklyFleetExpenses(operatingWeekStart):
Filters fuel and maintenance entries between Sunday and Saturday for each vehicle.
Aggregates weekly totals to feed overall company profitability reports.
