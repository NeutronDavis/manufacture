# TASK: Implement Sales Rep Route Loading, Daily Credit Reconciliation & Supermarket POS Module

## Architectural Rationale & Business Justification (The "Why")

### 1. Separation of Order Placement vs. Physical Distribution Loading
Sales reps submit daily stock requests (`Orders Placed`) [1, 2]. However, actual physical vehicle loading (`Quantity Loaded`) must be logged independently by dispatch staff [3]. A rep requesting 100 Jumbo loaves may only receive 50 due to factory production limits [3]. Route sheets and financial expectations must be calculated strictly from **signed-off loaded stock** [3].

### 2. Route Returns, Damaged Goods & Inventory Rollover Math
Upon route completion, the sales manager records actual verified sales [4, 5]. Unsold inventory is retained in the rep's vehicle as **Closing Stock** [4]. Damaged or spoiled goods are recorded separately for stock write-off [3, 4]. On subsequent days, newly loaded stock is added to the rep's carried-over closing stock to establish active route inventory [4, 6]:
\\[\text{Active Route Inventory Today} = \text{Yesterday's Closing Stock} + \text{Today's Newly Loaded Stock}\\]

### 3. Aggregated Lump-Sum Cash Collection & Running Credit Balances
Reps frequently collect past debts from supermarket accounts or issue new route credit, meaning daily cash/transfer collections rarely match that day's exact sales volume [5-7]. **Staff MUST NOT be forced to break down cash collections by individual product sizes/SKUs** [7]. Instead, the system records total cash/transfers collected as a single daily transaction and automatically computes the rep's running account balance [5, 7]:
\\[\text{New Account Balance} = \text{Previous Balance} + \text{Expected Today's Sales Value} - \text{Total Payments Collected Today}\\]

### 4. POS & Supermarket Accounts
Supermarket and POS accounts have custom agreed selling prices set centrally in Admin [8, 9]. When inventory is supplied to a supermarket account, the system records the supply, **automatically deducts the items from system inventory**, and charges the total monetary value to that account's running credit balance [9, 10].

## 1. DTO & Data Contract Specifications

Create or update the following Data Transfer Objects:

```typescript
export type ProductCategory = 'BREAD' | 'WATER' | 'POPCORN';

export interface RouteSKUItemDTO {
  productId: string;
  productName: string;
  category: ProductCategory;
  unitSellingPrice: number;          // Sourced from Admin Price Master
  
  // Daily Route Inventory Flow
  yesterdayClosingStock: number;     // Carried over from previous day
  todayNewlyLoadedQty: number;       // Logged independently by dispatch
  totalActiveInventory: number;      // (yesterdayClosingStock + todayNewlyLoadedQty)
  
  qtySold: number;                   // Recorded at route closing
  qtyReturned: number;               // Unsold closing stock retained in vehicle
  qtyDamaged: number;                // Spoiled/defective items
  
  expectedItemRevenue: number;       // (qtySold * unitSellingPrice)
}

export interface DailyRepRouteSheetDTO {
  id: string;
  routeSheetRef: string;             // e.g., "RTE-20261014-01"
  date: string;                      // YYYY-MM-DD
  repId: string;
  repName: string;
  repCode: string;                   // Assigned unique Rep ID (e.g., "REP-014")
  vehicleRegNumber: string;
  
  items: RouteSKUItemDTO[];
  
  // Daily Financial Reconciliation
  totalExpectedSalesRevenue: number; // SUM(qtySold * unitSellingPrice) across all SKUs
  previousAccountBalance: number;    // Cumulative balance before today's route
  
  // Lump-Sum Payments Collected (Aggregated — NO SKU breakdown)
  cashCollected: number;
  bankTransferCollected: number;
  posTerminalCollected: number;
  totalPaymentsCollectedToday: number; // (cash + transfer + pos)
  
  // Net Updated Running Balance
  newOutstandingAccountBalance: number; // (previousAccountBalance + totalExpectedSalesRevenue - totalPaymentsCollectedToday)
  
  status: 'ORDERED' | 'LOADED_ON_ROUTE' | 'RECONCILED' | 'CLOSED';
}

export interface SupermarketPOSAccountDTO {
  id: string;
  accountName: string;               // e.g., "City Supermarket - Branch A"
  contactPerson: string;
  phone: string;
  assignedRepId: string;
  customAgreedPrices: Record<string, number>; // Map of productId -> custom Price
  currentOutstandingCredit: number;
}
